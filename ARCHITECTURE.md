# Architecture

> Pair project: [dsh-remote-hub](https://github.com/yhuan416/dsh-remote-hub) ·
> Compatibility: [COMPATIBILITY.md](COMPATIBILITY.md) · Changelog: [CHANGELOG.md](CHANGELOG.md)

## Role

`dsh-remote-agent` is the **remote-side** half of the remote-dsh setup. It runs inside every
backend `dsh web` process and publishes that process's launch token + identity to a small JSON
file, so a hub can mint a remote browser cookie without scraping logs or pasting tokens by hand.

It does not proxy, tunnel, expose HTTP routes, or add tools. It only writes one file.

```text
remote dsh web (this plugin loaded)
  ├─ launch token generated by dsh for this process
  └─ $DSH_HOME/remote-agent.json   (0600, atomic, refreshed every 60s, removed on shutdown)
            ▲
            │ read over ssh by dsh-remote-hub (tokenFile.kind = "ssh")
hub dsh web ┘
```

## Runtime

1. **Startup** — schedule an immediate publish.
2. **Token discovery** — `ctx.webServer.getOrigin()` gives the listening origin;
   `ctx.connection.authenticatedUrl(origin + '/')` returns a URL carrying the process launch
   token. If the token is not available yet, retry every 200 ms up to 50 times.
3. **Write** — `<dshHome>/remote-agent.json` (or `config.file`), 0600, temp file + rename;
   parent directory created 0700 when missing.
4. **Heartbeat** — rewrite the same payload every 60 s (fresh `updatedAt`, same token), so the
   file is also a liveness hint.
5. **Shutdown** — `ctx.effect` cleanup clears the timers and unlinks the file. A crash leaves a
   stale file; the hub's probe fails and retries, and the next publish replaces it.

## Payload (file version 1)

```json
{
  "version": 1,
  "hostname": "yhuan-n100",
  "pid": 2533885,
  "startedAt": 1792413884370,
  "updatedAt": 1794197394348,
  "token": "<43-char launch token>",
  "webPort": 3080,
  "dshHome": "/home/yhuan/.dsh"
}
```

The hub's `tokenFile: { kind: 'ssh', host, user, path }` reads this file; `webPort` tells the hub
which remote port to tunnel to, and `hostname`/`pid` help diagnostics.

## Config

```yaml
- insert:
    - id: remote-agent
      name: dsh-remote-agent
      config:
        file: /custom/path/remote-agent.json   # optional
```

A generated settings form appears when the profile can resolve `@deepseek-ai/schemastery`.
Without it the plugin still works with defaults.

## Security

- The token is a credential: the file is 0600 and the parent is created 0700 when missing.
  Existing parent permissions are not changed.
- Nothing is sent over the network by this plugin; the hub reads the file server-side over ssh.
- The file is removed on graceful shutdown. Rotate the token by restarting the remote dsh; the
  file is rewritten on the next publish.
- Do not copy `remote-agent.json` into a repository or a container image.

## Deliberately not implemented

- HTTP endpoints or a discovery protocol (the hub already has an ssh transport).
- Multi-process coordination: one dsh process per `DSH_HOME`/file path. Running two processes
  with the same `DSH_HOME` would race on the same file; use `config.file` to separate them.
